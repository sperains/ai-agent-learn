## 目标

完成本课后，能够说明上下文窗口同时容纳输入和预留输出，计算历史消息可用预算，并区分 Token 计数与预算判断的职责。

## 概念边界

Token 是模型处理文本的切分单位，不等于字符数或单词数。不同语言、标点、空格和模型分词器都可能让相同长度的文本得到不同 Token 数。

`TokenCounter` 的职责是将文本换算为 Token 数。`ContextBudget` 的职责是根据已经得到的 Token 数判断请求能否发送，以及历史消息还剩多少可用预算。本课的实验只实现预算判断，不实现真实分词。

上下文窗口需要同时给系统规则、历史、当前用户消息和模型输出留空间。删除历史可以降低输入长度，但当系统规则、当前用户消息和预留输出本身已经超限时，删除历史无法解决问题。

## 核心事件链

```text
文本经 TokenCounter 得到 Token 数
  → 应用为模型输出预留 Token
  → ContextBudget 汇总系统、历史和当前用户消息的 Token
  → 未超过上限：发送请求
  → 超过上限：缩短输入、减少输出预留或切换更大窗口
```

预算约束为：

```text
系统 Token + 历史 Token + 当前用户 Token + 输出预留 Token ≤ 上下文窗口上限
```

## 实验与验证

业务实现位于 [src/main.py](src/main.py)，测试位于 [tests/test_lesson_03_token_budget.py](tests/test_lesson_03_token_budget.py)。

测试覆盖：

- 输入与输出预留总量未超过上限时允许发送；
- 历史消息超过可用预算时拒绝发送；
- 为系统规则、当前用户消息和输出预留后，正确计算历史可用 Token；
- 输出预留大于上下文上限时拒绝无效配置。

执行：

```bash
uv run pytest
```

2026-09-02 的完整结果为 `13 passed`。
