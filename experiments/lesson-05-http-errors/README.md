## 目标

完成本课后，能够区分超时、限流、客户端错误和服务端错误，并根据错误类别判断是否适合自动重试。

## 概念边界

一次 HTTP 请求经过应用、网络和服务端。应用超时只表示在截止时间前未收到响应，不能证明服务端一定未收到或未处理请求。

`429` 表示暂时限流，`5xx` 常表示服务端暂时故障，二者可以在受限条件下重试。`400` 一类客户端错误通常说明请求本身有问题，未改变请求前重复发送没有意义。

本课的分类是最小策略。生产环境需要结合具体状态码、服务端返回的等待建议、幂等性和调用成本制定策略。可重试不等于立刻无限重试，必须限制次数并逐步延长间隔。

## 核心事件链

```text
应用发起 HTTP 请求
  → 网络与服务端处理
  → 成功：收到响应
  → 失败：捕获异常或状态码
  → classify_error 分类
  → is_retryable 判断是否允许受控重试
  → 重试、返回错误或进入后续降级处理
```

## 学习者的掌握证据

- 能说明超时不能证明服务端未收到请求，原因可能是处理、网络或响应链路。
- 能说明 `429` 与 `400` 的差别，以及为什么前者比后者更适合自动重试。
- 能说明立即无限重试会重复失败、消耗资源并放大服务端压力。
