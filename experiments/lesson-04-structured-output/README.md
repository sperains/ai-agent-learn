## 目标

完成本课后，能够区分 JSON 语法正确和业务结构有效，并在模型输出不符合程序契约时明确失败。

## 概念边界

Prompt 可以提高模型按指定格式返回的概率，不能保证结果一定满足程序要求。程序必须在使用模型结果前解析并校验。

JSON 解析只验证文本能否成为 JSON 数据。结构校验还要验证顶层类型、字段类型和业务允许的取值。`{"urgent": "yes"}` 是合法 JSON，但 `urgent` 是字符串，不能直接作为布尔值使用。

本课的最小实验遇到无效模型响应时抛出明确错误。生产系统可在此基础上增加有限次数重试、原始响应记录、降级和人工介入，但不能用默认值伪装未知结果。

## 核心事件链

```text
模型返回文本
  → JSON 解析
  → 顶层对象校验
  → urgent 类型校验
  → category 允许值校验
  → 生成 TaskClassification
  → 程序使用已验证的结果
```

任一校验失败时，停止业务处理并返回错误。

## 实验与验证

业务实现位于 [src/main.py](src/main.py)，测试位于 [tests/test_lesson_04_structured_output.py](tests/test_lesson_04_structured_output.py)。

测试覆盖：

- 合法输出可解析为 `TaskClassification`；
- 非 JSON 文本被拒绝；
- `urgent` 为字符串时被拒绝；
- `category` 不在 `bug` 和 `question` 范围内时被拒绝。

执行：

```bash
uv run pytest
```

2026-09-02 的完整结果为 `17 passed`。

## 学习者的掌握证据

- 能说明合法 JSON 不等于可被业务代码安全使用的结构。
- 能说明 Prompt 不能替代程序校验，因为模型输出并不绝对稳定。
- 能说明校验失败应明确返回错误，而不是静默使用默认值。
- 能提出在生产系统中增加提示词改进、有限重试和失败记录。
