## 目标

完成本课后，能够解释一次模型调用的输入、输出和失败位置，并通过稳定接口替换固定模型与真实模型实现。

## 概念边界

模型调用是应用将消息交给模型实现并取得响应的一次请求。它还不是 Agent，因为没有根据结果继续判断、调用工具或控制循环。

`Model` 描述共同契约：接收 `list[Message]`，返回文本响应。`FixedResponseModel` 是这个契约的一个实现，用于在不依赖网络、密钥和真实模型服务时重复验证应用行为。将来可以替换为真实模型实现，应用层仍通过相同的 `generate` 方法调用。

消息为空属于调用前可判断的无效输入。模型实现必须抛出明确错误，不能返回看似成功的固定文本，否则调用方无法定位错误来自输入而非模型响应。

## 核心事件链

```text
应用构造 Message 列表
  → 应用函数接收 Model 契约与消息
  → Model.generate 校验输入
  → 有效输入：模型返回响应
  → 无效输入：模型抛出明确错误
  → 应用处理响应或错误
```

替换实现时的依赖关系：

```text
应用层 → Model 契约 → FixedResponseModel 或真实模型实现
```

应用层只依赖 `generate(messages)` 的输入输出，不读取某个实现的内部字段。

- 能说明固定响应模型用于隔离真实服务的不确定性，观察输入、接口调用和响应处理的最小事件链。
