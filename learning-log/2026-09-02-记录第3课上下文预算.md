# 记录第 3 课上下文预算

## 本次目标

理解 Token、上下文窗口和输出预留如何共同决定一次模型调用能否发送。

## 已完成

- 实现上下文预算对象，判断请求是否超过上限。
- 计算为系统规则、当前用户消息和输出预留后可分配给历史的最大 Token 数。
- 覆盖正常预算、历史超限、历史可用预算和无效输出预留四类测试。
- 区分 Token 计数与预算判断职责，避免将模型分词变化耦合到预算规则中。
- 完整测试得到 `13 passed`。

## 当前结论

上下文窗口是输入和输出共同使用的有限容量。历史并非总能通过删除来解决超限，系统规则、当前输入和输出预留也可能单独超过容量。预算组件只处理已知 Token 数，真实文本计数应由可替换的计数器承担。
