# 全阶段课程地图

课程地图确保学习方向完整，详细教案则按四课一个批次逐步生成。课程编号和能力目标保持稳定；模型、框架和示例可以根据届时的官方文档更新。

## 课程结构

| 课程范围 | 阶段 | 阶段成果 |
|---|---|---|
| 01～12 | 入门与最小 Agent | 手写可测试的 Agent Loop |
| 13～20 | 工具与任务执行 | 安全、可控的工具系统 |
| 21～28 | 状态与上下文 | 可暂停、恢复的任务运行时 |
| 29～36 | RAG 与记忆 | 可评测、可引用的知识系统 |
| 37～44 | 工作流与多 Agent | 可编排、可恢复的复杂任务系统 |
| 45～52 | 评测与可观测性 | 可量化、可回归的质量体系 |
| 53～60 | 生产化与系统设计 | 可部署、可治理的企业级服务 |
| 61～68 | 综合项目与面试 | 可演示、可答辩的岗位证据包 |

01～12 的详细内容见 [curriculum.md](curriculum.md)。以下是后续课程的稳定能力骨架。

## 13～20：工具与任务执行

| 课次 | 主题 | 必须形成的能力 |
|---|---|---|
| 13 | 工具契约与注册表 | 分离模型描述、参数结构和真实执行函数 |
| 14 | 参数校验与错误分类 | 拒绝不可信参数并给出可处理错误 |
| 15 | 超时、重试与退避 | 区分瞬时错误和永久错误 |
| 16 | 幂等与副作用 | 防止重试造成重复写入 |
| 17 | 权限与最小授权 | 按用户、任务和工具限制能力 |
| 18 | 人工审批与审计 | 对高风险动作建立确认和追踪链路 |
| 19 | 工具协议与 MCP 边界 | 理解协议解决的问题及安全边界 |
| 20 | 阶段验收 | 交付安全工具系统证据包 |

## 21～28：状态与上下文工程

| 课次 | 主题 | 必须形成的能力 |
|---|---|---|
| 21 | 会话历史与任务状态 | 分离“说过什么”和“执行到哪里” |
| 22 | 状态模型与检查点 | 定义可持久化的执行状态 |
| 23 | 上下文分层与信任 | 标记来源、优先级和可信度 |
| 24 | Token 预算与选择 | 在窗口限制内选择有效信息 |
| 25 | 摘要与压缩 | 控制信息损失并保留关键状态 |
| 26 | 短期与长期记忆 | 定义写入、读取、更新和遗忘策略 |
| 27 | 暂停、恢复与取消 | 从检查点安全恢复任务 |
| 28 | 阶段验收 | 交付可恢复运行时证据包 |

## 29～36：RAG 与记忆系统

| 课次 | 主题 | 必须形成的能力 |
|---|---|---|
| 29 | 文档解析与清洗 | 将来源转成可追踪的数据单元 |
| 30 | 分块策略 | 根据文档结构和查询目标切分内容 |
| 31 | Embedding 与向量检索 | 理解语义召回及其限制 |
| 32 | 关键词与混合检索 | 组合精确匹配和语义召回 |
| 33 | 查询改写与重排 | 提升候选内容的相关性 |
| 34 | 生成、引用与拒答 | 让回答可验证并在证据不足时停止 |
| 35 | 记忆写入与遗忘 | 控制错误记忆和隐私风险 |
| 36 | 阶段验收 | 交付检索评测与失败归因报告 |

## 37～44：工作流与多 Agent

| 课次 | 主题 | 必须形成的能力 |
|---|---|---|
| 37 | 固定工作流与 Agent 边界 | 根据不确定性选择执行模式 |
| 38 | 路由与任务分解 | 把复杂目标转换为可执行节点 |
| 39 | 状态机与节点契约 | 明确定义转移条件和节点输入输出 |
| 40 | 并发与依赖调度 | 安全执行并行任务并汇总结果 |
| 41 | 人工介入 | 设计暂停、审批和补充信息流程 |
| 42 | 部分失败与补偿 | 处理回滚、补偿和降级 |
| 43 | 多 Agent 协作边界 | 用评测判断是否真的需要多 Agent |
| 44 | 阶段验收 | 交付复杂任务编排证据包 |

## 45～52：评测与可观测性

| 课次 | 主题 | 必须形成的能力 |
|---|---|---|
| 45 | 评测目标与数据集 | 从业务目标定义可测任务 |
| 46 | 确定性测试与模型替身 | 分离程序错误和模型波动 |
| 47 | 检索质量评测 | 测量召回、排序和引用质量 |
| 48 | 轨迹与工具调用评测 | 检查过程是否安全有效 |
| 49 | 模型裁判与人工评审 | 识别自动评测偏差 |
| 50 | Trace 与失败分类 | 还原一次任务的完整执行链 |
| 51 | 延迟、Token 与成本 | 建立质量、速度和费用权衡 |
| 52 | 阶段验收 | 交付可重复的回归评测系统 |

## 53～60：生产化与系统设计

| 课次 | 主题 | 必须形成的能力 |
|---|---|---|
| 53 | 服务接口与异步任务 | 将 Agent 运行时暴露为可靠服务 |
| 54 | 数据库、缓存与队列 | 管理状态、并发和任务调度 |
| 55 | 鉴权、多租户与隔离 | 防止跨用户和跨组织数据泄露 |
| 56 | 提示注入与数据外泄 | 建立输入、工具和输出防线 |
| 57 | 限流、降级与模型路由 | 控制容量、成本和供应商风险 |
| 58 | 部署、监控与告警 | 建立可运营的运行环境 |
| 59 | 故障演练与回滚 | 验证恢复目标和应急流程 |
| 60 | 架构评审 | 完成生产系统设计答辩 |

## 61～68：综合项目与岗位准备

| 课次 | 主题 | 必须形成的能力 |
|---|---|---|
| 61 | 业务问题建模 | 判断 Agent 是否适合解决目标问题 |
| 62 | 架构方案与决策记录 | 用约束和证据解释技术选择 |
| 63 | 端到端核心链路 | 集成已通过验收的阶段能力 |
| 64 | 评测驱动优化 | 根据失败数据优化而非凭感觉调参 |
| 65 | 安全与可靠性审查 | 修复权限、注入和恢复风险 |
| 66 | 部署与演示 | 提供可复现的真实演示环境 |
| 67 | 作品集与面试表达 | 将代码证据转成岗位能力叙述 |
| 68 | 最终答辩 | 完成架构、故障和取舍的综合考核 |

## 允许调整的内容

- 课程可以因掌握速度拆分或合并，但能力目标不能静默删除；
- 框架和模型示例可以更新，但必须保留不依赖框架的原理解释；
- 新增内容必须说明它对应哪个岗位能力，不能只因热门而插入；
- 每次调整都记录原因、影响课程和验证方式。
