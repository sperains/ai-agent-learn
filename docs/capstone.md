# 贯穿式综合项目

综合项目暂定为“可恢复的任务执行 Agent”。它不是最后才开始的新项目，而是从第一阶段开始持续演进。

## 演进路线

| 阶段 | 项目增量 | 可观察结果 |
|---|---|---|
| 入门 | 模型适配层和固定响应 | 无外部服务也能重复实验 |
| 一 | 最小 Agent Loop | 能完成一次判断、工具调用和终止 |
| 二 | 工具注册、权限、审批和幂等 | 错误参数被拒绝，高风险操作受控 |
| 三 | 任务状态和上下文管理 | 中断后能够从已保存状态恢复 |
| 四 | 知识检索与记忆 | 回答带来源，检索质量可单独测量 |
| 五 | 工作流、路由和人工介入 | 复杂任务可暂停、恢复和处理部分失败 |
| 六 | 评测、Trace 和成本 | 每次变更都有可比较的质量报告 |
| 七 | 鉴权、隔离、限流和部署 | 能完成生产架构与故障演练 |
| 八 | 作品集与面试材料 | 可演示、可讲解、可复现、可追责 |

## 架构约束

- 模型、工具、状态存储和观测都通过清晰接口替换；
- 本地固定响应始终可运行，真实模型是可选适配器；
- 每次只吸收当前阶段已经验收的能力；
- 未经数据证明，不为了“更像 Agent”引入多 Agent；
- 所有有副作用的工具都必须定义权限、幂等和审计策略。
